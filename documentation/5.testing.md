# Testing

> Twenty-one Playwright tests exercise the production build end to end — per-screen smoke checks, UI-driven drawing and measurements, undo/redo/clear, both export formats, automatic light/dark theming and repeatable README home and demo captures in both schemes — and any console error fails the test that produced it.

## Overview

- **Playwright, Chromium only.** A single project runs Desktop Chrome ([`playwright.config.ts:23-28`](../playwright.config.ts)); there is no unit-test runner in the stack (see [Architecture](2.architecture.md)).
- **The production build, not the dev server.** The `webServer` block runs `npm run build` before `vite preview` ([`playwright.config.ts:17-22`](../playwright.config.ts)), so tests check the real bundled output that ships to GitHub Pages.
- **Six specs share three auto-applied fixtures.** Every spec imports the extended `test`/`expect` from [`tests/e2e/fixtures.ts`](../tests/e2e/fixtures.ts), which fails tests on console errors, isolates `localStorage` and tracks finished map tiles (see below).
- **Twenty-one tests, one an intentional expected failure.** The three meta-tests in [`fixture-self-test.spec.ts`](../tests/e2e/fixture-self-test.spec.ts) prove the fixtures and the capture guard work; the console-error one is marked with `test.fail()`, so the suite still exits 0. Once the browser is installed, the demo captures and the theme-swap tests dominate the runtime (excluding the one-off build).

## Fixtures and Policy

[`fixtures.ts`](../tests/e2e/fixtures.ts) extends Playwright's `test` with three fixtures, all `{ auto: true }` so they apply to every test without being requested:

- **`failOnConsoleError`** ([`fixtures.ts:58-85`](../tests/e2e/fixtures.ts)) collects every `console` message of type `error` and every uncaught `pageerror`, then fails the test during teardown with a message that includes the current page URL and each collected message. Console `warning`s are logged to the test output but never fail a test.
- **`cleanStorage`** ([`fixtures.ts:24-38`](../tests/e2e/fixtures.ts)) runs `context.addInitScript` to remove the app's `localStorage` keys — `terra-draw` (feature snapshot) and `tab` (active side-panel tab) — before app scripts run on every navigation. Each test therefore starts from the default state: Info tab, no features.
- **`mapTileTracker`** ([`fixtures.ts:40-56`](../tests/e2e/fixtures.ts)) records every finished Protomaps map-tile request per page from before navigation, matching the `/tiles/v<N>/<z>/<x>/<y>.mvt` URL shape. It listens on `requestfinished` rather than `response` so the tile body is fully downloaded; [`getMapTileUrls(page)`](../tests/e2e/fixtures.ts) ([`fixtures.ts:96-98`](../tests/e2e/fixtures.ts)) exposes the live list.

Because all three fixtures are auto-applied, specs must import `test`/`expect` from `./fixtures`, not `@playwright/test`.

[`fixtures.ts`](../tests/e2e/fixtures.ts) also exports `captureScreenshot(page, path)` ([`fixtures.ts:428-467`](../tests/e2e/fixtures.ts)), which gates on map rendering and validates the captured bytes before writing. Chromium can transiently reject `Page.captureScreenshot` while several headless browsers render WebGL maps; those protocol errors are retried with linear backoff (400 ms, then 800 ms — three attempts in all). Independently, Chromium can return a *successful* screenshot with blank map pixels (a WebGL readback race, seen as `GPU stall due to ReadPixels` warnings). Each attempt therefore decodes its own PNG buffer and counts exact colours in a chrome-free band of the map region ([`fixtures.ts:342-384`](../tests/e2e/fixtures.ts)) — below the drawing toolbar and above the attribution control, whose antialiased pixels would let a blank map score 40+. A blank band scores 1 colour against the more than 32 required ([`fixtures.ts:319`](../tests/e2e/fixtures.ts)); the four committed map assets score 139–960. A blank result triggers `nudgeMapRepaint` ([`fixtures.ts:394-404`](../tests/e2e/fixtures.ts)), a one-pixel viewport resize that MapLibre's `ResizeObserver` turns into `map.resize()` plus a fresh frame, then re-runs `waitForMapTilesReady` and waits the backoff before retrying. The file is written only after validation, so a failed or blank capture never reaches disk; if every attempt is blank the helper throws with the path and the colour count. `smoke.spec.ts`, `demo-screenshot.spec.ts` and `dark-mode.spec.ts` all use it, so every current and future capture is gated.

### Readiness Without Sleeps

Tests never use `page.waitForTimeout` or wait for `networkidle`. The readiness signal is the `#select` toolbar button: `MapButtons` is only rendered once Terra Draw exists ([`home/index.tsx:151-153`](../src/routes/home/index.tsx)), and Terra Draw is only constructed after MapLibre's `style.load` fires ([`home/index.tsx:53-55,62-65`](../src/routes/home/index.tsx)). Waiting for `#select` therefore proves the real map pipeline ran — UI readiness only, not that tiles were fetched or painted. Screenshot captures use a separate render gate (below).

> [!NOTE]
> Several console warnings appear routinely on healthy runs and are non-fatal: Chromium/ANGLE's `GPU stall due to ReadPixels` (map rendering), `Setting overlaysContent is only supported from the top level browsing context` (the cross-origin TypeDoc iframe) and MapLibre's asynchronous `Image "…" could not be loaded` on the first marker draw — the last is pre-existing and reproduces in light mode with no style swap. The demo spec adds around 16 MapLibre `Max vertices per segment is 65535: bucket requested ...` warnings while rendering the 69,577-coordinate line; the line still renders fully because MapLibre splits segments. The fixture fails on `error` and `pageerror` only.

### Screenshot Gating — `waitForMapTilesReady`

Every capture through `captureScreenshot` first awaits [`waitForMapTilesReady(page)`](../tests/e2e/fixtures.ts) ([`fixtures.ts:262-310`](../tests/e2e/fixtures.ts)), a hard gate that refuses to capture until the map is actually painted:

1. **Non-map screens return immediately.** The gate checks for `#maplibre-map`; the `/#/api/` TypeDoc route has none, so it is a no-op there.
2. **Finished tiles.** It polls the `mapTileTracker` list for at least 4 finished tiles (30 s timeout). The default 1280×720 viewport has a 780×650 map, which needs 4–6 of MapLibre's 512px tiles at the default zoom — 4 proves real coverage without being brittle about edge tiles. `requestfinished` matters: `response` fires before the tile body completes.
3. **Painted canvas.** It then polls a downscaled 160×160 capture of `.maplibregl-canvas` for more than 10 distinct quantised colours (30 s timeout). A blank or uniform canvas yields 1–3 colours; a painted map with labels yields hundreds.
4. **Compositor settle.** A final double `requestAnimationFrame` lets the compositor catch up before the screenshot.

Both polls fail loudly — never silently — after 30 s, throwing with the page URL and counts (`… Refusing to capture a blank map.`). Why the pixel check: probes showed 4 tiles already *fetched* while the canvas was still blank — the race is parse-and-paint, not fetch — and a double `requestAnimationFrame` alone was not load-proof under the parallel suite (a full-suite capture went blank again). Canvas colour diversity is load-independent because it gates on the pixels the screenshot will actually contain.

Verified failure mode: blocking `protomaps.com/tiles/` makes the gate throw with `only 0 finished tile request(s) … Refusing to capture a blank map`, and the console-error fixture additionally flags MapLibre's tile-load errors — the suite fails rather than committing a blank asset. The gate adds roughly 0.5–1.5 s per map capture.

This gate proves the *live canvas* painted, which is necessary but not sufficient: a later full-viewport capture can still read back blank pixels, so `captureScreenshot` additionally validates the captured bytes and retries a blank result (see above). That guard has its own meta-test ([`fixture-self-test.spec.ts:38-70`](../tests/e2e/fixture-self-test.spec.ts)), which stubs `page.screenshot` with a 1×1 blank PNG and asserts the loud rejection plus nothing reaching disk.

## Coverage

### Smoke — `smoke.spec.ts`

Both smoke tests write a full-page screenshot to [`documentation/screenshots/`](screenshots/) — a tracked directory checked into version control, so each image is reviewable in Git diffs and can be linked from documentation — and attach the same image to the Playwright HTML report.

**Home screen (`/#/`)** ([`smoke.spec.ts:6-38`](../tests/e2e/smoke.spec.ts)): title matches `/Terra Draw/i`; the `Home`, `API Docs` and `Sponsor` links are visible; the Info and GeoJSON tabs and the `Collapse side panel` button are visible. The default state is asserted too — the `All Features` heading is visible and the feature table has zero rows (guaranteed by storage isolation) — and map readiness waits for `#maplibre-map` and `#select`. The test then explicitly awaits `waitForMapTilesReady`, making real tile rendering part of the assertion rather than an assumption. This regenerates the committed light home capture, [`documentation/screenshots/home-light.png`](screenshots/home-light.png), and attaches it to the report as `smoke-home`; the dark counterpart comes from the capture test in [`dark-mode.spec.ts`](../tests/e2e/dark-mode.spec.ts).

![Home screen: the map demo with the default Info tab and no features drawn](screenshots/home-light.png)

**API docs screen (`/#/api/`)** ([`smoke.spec.ts:40-56`](../tests/e2e/smoke.spec.ts)): exactly one visible `iframe`, with `src` equal to `https://jameslmilner.github.io/terra-draw/modules.html`. The content is cross-origin and is not asserted. The shared capture gate is a no-op on this screen, which has no `#maplibre-map`. The screenshot is written to [`documentation/screenshots/api-docs.png`](screenshots/api-docs.png) and attached as `smoke-api`.

### Drawing — `drawing.spec.ts`

Drawing is entirely UI-driven: modes are clicked in the toolbar, vertices are clicked on the map canvas, and shapes are finished with `Enter`. Map clicks are computed from the `#maplibre-map` bounding box and kept clear of the toolbar (two rows at the default 1280×720 viewport), the side panel and the attribution control ([`drawing.spec.ts:10-26`](../tests/e2e/drawing.spec.ts)).

- **Polygon** ([`drawing.spec.ts:46-83`](../tests/e2e/drawing.spec.ts)): `#polygon` gains the active class; Total and Polygons badges show `1`; one feature row appears. Selecting the row shows `Selected Feature Measurements` with a numeric `Area (m2)`/`Area (km2)` badge and a numeric `Coordinates` value. The GeoJSON tab parses to a `FeatureCollection` containing a `Polygon`.
- **Line** ([`drawing.spec.ts:85-113`](../tests/e2e/drawing.spec.ts)): `#linestring` gains the active class; Lines and Total badges show `1`; selection shows a numeric `Length (km)`. The GeoJSON tab contains a `LineString`.
- **Undo, redo and clear** ([`drawing.spec.ts:115-155`](../tests/e2e/drawing.spec.ts)): undo and redo start disabled; after drawing a point, undo removes it and enables redo, which restores it; clear zeroes all four badges, empties the table, removes the `terra-draw` `localStorage` key and leaves an empty `FeatureCollection` in the GeoJSON tab.

### Export — `export.spec.ts`

Downloads are triggered through the GeoJSON tab and observed via Playwright's `download` event.

- **GeoJSON** ([`export.spec.ts:54-87`](../tests/e2e/export.spec.ts)): the filename matches `terradraw_<timestamp>.geojson`; the file parses as a `FeatureCollection` containing the drawn polygon; its bytes are identical to the GeoJSON textarea.
- **FlatGeobuf** ([`export.spec.ts:89-112`](../tests/e2e/export.spec.ts)): the filename matches `terradraw_<timestamp>.fgb`; the file is non-empty and carries the FlatGeobuf magic bytes (`fgb`) followed by format version 3.

`<timestamp>` follows `fileDate()` ([`utils/dates.ts:11-17`](../src/utils/dates.ts)).

### Automatic theming — `dark-mode.spec.ts`

The spec proves the theme contract through public interfaces only — computed styles, network requests and canvas pixels — using Playwright's per-test colour scheme rather than app internals.

- **Light guards** ([`dark-mode.spec.ts:155-175`](../tests/e2e/dark-mode.spec.ts)): with `colorScheme: "light"`, body and header backgrounds and body text must equal the exact shipped values (`rgb(250, 250, 250)`, `rgb(253, 253, 253)`, `rgb(68, 68, 68)`), and the logo and GitHub marks must have no CSS filter. This is the regression guard for the light-identical guarantee.
- **Dark invariants** ([`dark-mode.spec.ts:177-241`](../tests/e2e/dark-mode.spec.ts)): with `colorScheme: "dark"`, both routes must compute to dark surfaces and light text (WCAG relative-luminance thresholds, deliberately loose so palette tweaks do not break the suite), header marks must be inverted, and the first load must request the dark Protomaps style. The home route's capture test — *captures the README dark home capture* — writes the committed [`documentation/screenshots/home-dark.png`](screenshots/home-dark.png) through the full `captureScreenshot` guard and attaches it as `home-dark`. The API docs route's dark evidence stays uncommitted in `.opencode/tmp/dark-mode/api-docs-dark.png` — a gitignored temporary path — and is attached as `dark-api-docs`.
- **Live switching** ([`dark-mode.spec.ts:243-373`](../tests/e2e/dark-mode.spec.ts)): starting light, `page.emulateMedia` flips to dark and back, asserting `white.json` → `black.json` → `white.json` style requests and canvas luminance in each state. The second test draws a polygon, a point and a marker *after* the swap and asserts all three persist through the reverse swap, covering the image-dependent `td-point-marker` layer.

### Fixture self-tests — `fixture-self-test.spec.ts`

- Logs a deliberate `console.error` and marks the test `test.fail()`, proving `failOnConsoleError` fails tests that emit errors while the suite still exits 0 ([`fixture-self-test.spec.ts:17-28`](../tests/e2e/fixture-self-test.spec.ts)).
- Stubs `page.screenshot` with a 1×1 blank PNG and asserts `captureScreenshot` rejects with `Refusing to write a blank screenshot` and leaves no file on disk ([`fixture-self-test.spec.ts:38-70`](../tests/e2e/fixture-self-test.spec.ts)). The stub makes the readback race deterministic instead of probabilistic.
- Writes both app keys, reloads and asserts `localStorage` is clean, proving the isolation script runs before app scripts ([`fixture-self-test.spec.ts:76-93`](../tests/e2e/fixture-self-test.spec.ts)).

### Demo captures — `demo-screenshot.spec.ts`

[`demo-screenshot.spec.ts`](../tests/e2e/demo-screenshot.spec.ts) regenerates the two committed README demo captures — [`documentation/screenshots/demo-light.png`](screenshots/demo-light.png) and [`demo-dark.png`](screenshots/demo-dark.png), both 1440×900 — from a single Terra Draw-native LineString on every suite run, attaching them to the report as `demo-light` and `demo-dark`. It runs under a 120 s timeout with `reducedMotion: "reduce"`.

- **Seeding.** A later-registered `context.addInitScript` writes `collection.features` straight into the app's `terra-draw` `localStorage` key after the `cleanStorage` fixture's script, so the seed survives every navigation. The restore path is asserted for real: Total `1`, Lines `1`, Points `0`, Polygons `0`, and one table row.
- **Fixture provenance.** [`tests/data/big-route.geojson`](../tests/data/big-route.geojson) is a Terra Draw-native FeatureCollection — one 2D `LineString` with 69,577 coordinates and `properties.mode: "linestring"` (1.58 MB, compact). It was derived once from a previous route export: all 19 line features (14 `MultiLineString`s → 40 parts, plus 5 `LineString`s) merged in order, altitude stripped, the 257 photo `Point`s and all other properties dropped, with no rounding or decimation and no consecutive duplicates. The original multi-feature export was untracked and is not in the repo.
- **Export before selection.** The GeoJSON textarea is parsed before any row click and asserted exactly: one feature, `LineString`, 69,577 coordinates, a 2D first coordinate and `properties.mode === "linestring"`. Selection is deliberately avoided — see the dense-feature caveat under [Caveats](#caveats).
- **Deterministic framing.** Mocked geolocation plus reduced motion makes the `#geolocation` click an instant, exact centre + zoom 14 jump; eight `-` keypresses step out to zoom 6, and one isolated wheel event trims to zoom 5.7998 (tile zoom 5). Framing is pixel-identical across consecutive regenerations.
- **Shared tracker and overwrite safety.** The spec reads the shared [`getMapTileUrls(page)`](../tests/e2e/fixtures.ts) tracker instead of attaching its own listener. On top of the generic render gate that `captureScreenshot` applies, it waits for at least three finished tiles at the final camera's zoom (`/tiles/v3/5/...`) before returning to the Info tab and letting the light capture overwrite the committed image.
- **Dark capture mid-scene.** After the light capture, `page.emulateMedia({ colorScheme: "dark" })` fires the app's `matchMedia` listener, swapping the basemap live to `black.json` while the `transformStyle` carry-over preserves the seeded route layer. The test gates on `mapCanvasLuminance(page)` dropping below `0.2` — a style request alone would not prove the dark basemap had painted — then captures `demo-dark.png` through the same guard and attaches it as `demo-dark`.

Regenerate just the demo captures with `npx playwright test tests/e2e/demo-screenshot.spec.ts`; a full `npm test` also rewrites them.

## Running the Tests

Playwright's browser is a separate download. Install it once per machine, then run the suite ([Getting started](1.start.md) covers the broader setup):

```bash
npx playwright install --with-deps chromium
npm test
```

`npm test` runs `playwright test --config=playwright.config.ts` ([`package.json:10`](../package.json)). Before the first test, Playwright starts:

```
npm run build && npx vite preview --host 127.0.0.1 --port 4173 --strictPort
```

and waits for `http://127.0.0.1:4173` with a 120-second budget. Locally an existing server on port 4173 is reused (`reuseExistingServer: !process.env.CI`); in CI a fresh one is always started.

> [!WARNING]
> `npm test` starts with `npm run build`, so it wipes and rewrites `docs/` — the Vite build output ([Deployment](6.deployment.md)), which is gitignored. Never treat `docs/` as documentation.

> [!NOTE]
> `reuseExistingServer` means a stale preview left on port 4173 will be reused as-is. If local results look wrong, stop any running preview before retrying.

Screenshots are written to [`documentation/screenshots/`](screenshots/) by the smoke, demo and dark-mode specs — each capture render-gated and buffer-validated first (see [Fixtures and Policy](#fixtures-and-policy)) — and attached to the test report. Unlike the generated `test-results/` and `playwright-report/` directories, this directory is checked into version control: changes appear in Git diffs for review, and the images can be embedded in documentation. Five assets are committed: the light and dark home captures (`home-light.png`, `home-dark.png`), the light and dark demo captures (`demo-light.png`, `demo-dark.png`) and `api-docs.png` (the light view; the themed page chrome leaves the image unchanged). The only dark evidence left uncommitted is the API docs capture in the gitignored `.opencode/tmp/dark-mode/`. The default local `list` reporter does not display attachments — rerun with `npx playwright test --reporter=html` and open the report with `npx playwright show-report` to view them.

## Debugging

Playwright's CLI adds three useful modes (see [Playwright's debugging guide](https://playwright.dev/docs/debug)):

- `npx playwright test --headed` — watch the browser while tests run.
- `npx playwright test --debug` — headed with the Playwright Inspector (`PWDEBUG=1`); add `--timeout=0` to remove timeouts while stepping.
- `await page.pause()` in a spec — pauses at that line with the browser open; requires headed mode.

When working on map interactions, remember that readiness is gated on `#select`, vertices are clicks inside `#maplibre-map`, and this Terra Draw version has no double-click-to-finish: `Enter` finishes polygon/line shapes and `Escape` cancels them.

Traces from `trace: "on-first-retry"` land in `test-results/`, alongside reports in `playwright-report/`; both are gitignored ([`.gitignore:6-7`](../.gitignore)). The checked-in screenshots live separately in [`documentation/screenshots/`](screenshots/) and are not gitignored.

## Caveats

- **Specs are not type-checked.** `npm run typecheck` covers `src/**/*` only, so `playwright.config.ts` and the specs — which reference `process` without `@types/node` — are outside the program (see [Architecture](2.architecture.md), tech-debt item 12).
- **External runtime dependencies.** Map readiness depends on MapLibre's `style.load`, which needs a Protomaps style endpoint and API key ([`setup-maplibre.ts:65-68`](../src/routes/home/setup-maplibre.ts)), and the map-screen tests now need egress to `api.protomaps.com` for tile bodies. A blocked endpoint fails runs rather than merely slowing them, and the screenshot gates fail loudly rather than committing a blank asset. The API iframe is cross-origin, so its content is never asserted, and it emits the `overlaysContent` warning noted above.
- **Colour heuristic assumes a painted map.** The render gate's pixel check expects more than 10 distinct quantised colours; a uniform view (for example mid-ocean with no labels) could theoretically trip it. `waitForMapTilesReady` accepts `minimumTiles` and `timeout` overrides if a future capture legitimately needs different thresholds.
- **Area units vary with zoom.** `InfoTab` switches polygon area from `Area (m2)` to `Area (km2)` at 1,000,000 m² ([`InfoTab.tsx:8,62-74`](../src/components/info-tab/InfoTab.tsx)). At the default zoom a screen-visible polygon is always ≥ 1 km², so the drawing spec accepts either unit rather than pinning one.
- **Dense features stall selection.** Clicking the table row for the demo's 69,577-coordinate line never completes within the 120 s timeout: Terra Draw's select mode creates around two guidance features per coordinate (≈139k). Both demo captures are therefore taken unselected, with no `Selected Feature Measurements` section. This is app behaviour with very dense features, not a test defect.
- **Stale preview reuse.** `reuseExistingServer` reuses whatever is listening on port 4173 locally — stop any running preview before a verification run (see the note under [Running the Tests](#running-the-tests)).
