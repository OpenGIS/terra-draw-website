# Export and Measurement

> The side panel turns the current Terra Draw snapshot into counts, measurements and downloadable files — all in the browser, with no server round-trip.

The panel toggles between two tabs, both fed from the same `features` snapshot.

## Info Tab

[`InfoTab.tsx`](../src/components/info-tab/InfoTab.tsx) is the inventory and measurement view. Snapshots contain editing aids alongside real geometry: a feature is guidance when any of `selectionPoint`, `midPoint`, `closingPoint`, `snappingPoint`, `coordinatePoint` or `virtualPoint` is set, and the **Hide guidance features** checkbox (on by default) excludes them from the table, badges and measurements.

Badges show **Total**, **Polygons**, **Lines** and **Points**, classified by `geometry.type`; the table lists ID (first 8 characters), geometry type and `createdAt`/`updatedAt` timestamps, and clicking a row switches Terra Draw to select mode and highlights the feature (guidance rows are non-selectable).

For the selected feature:

| Geometry   | Measurement | Implementation                                            |
| ---------- | ----------- | --------------------------------------------------------- |
| Polygon    | Area        | Turf `area` in m², switched to km² at 1,000,000 m²        |
| LineString | Length      | Turf `length` in km                                       |
| Both       | Coordinates | Polygon outer-ring length, or LineString coordinate count |

Turf's default units are used (m² for `area`, km for `length`); both are re-exported through [`utils/geo.ts`](../src/utils/geo.ts) so components never import Turf directly.

## GeoJSON Tab

[`GeoJSONTab.tsx`](../src/components/geojson-tab/GeoJSONTab.tsx) wraps the snapshot in a `FeatureCollection`, stringifies it with 4-space indentation and shows it in a read-only `<textarea>`. A copy button appears only when `navigator.clipboard` exists. An export select offers **GeoJSON** or **FlatGeobuf**, with one Download button dispatching on the chosen format.

Filenames are `terradraw_<fileDate()>.geojson` or `.fgb`, where `fileDate()` is a filesystem-safe timestamp ([`utils/dates.ts`](../src/utils/dates.ts)). Both download hooks create a `Blob`, turn it into an object URL, click a detached anchor with a `download` attribute, then revoke the URL. JSON downloads as `text/plain` ([`useDownloadJSON.ts`](../src/components/geojson-tab/useDownloadJSON.ts)); FlatGeobuf dynamically imports the library, serialises to a `Uint8Array` and downloads as `octet/stream` ([`useDownloadFlatGeobuf.ts`](../src/components/geojson-tab/useDownloadFlatGeobuf.ts)), keeping `flatgeobuf` out of the initial bundle.

> [!NOTE]
> The FlatGeobuf import is a deep subpath (`flatgeobuf/lib/mjs/geojson`) that couples the code to the package's internal layout — check it on a major upgrade.

Everything is client-side: no API calls or uploads, measurements run during render via `useMemo`, and downloads use in-browser Blob URLs. Two caveats: clipboard writes need a secure context (`localhost` counts in development), and the downloaded GeoJSON is the raw snapshot — it can include guidance features, since the filter is an Info tab concern only.
