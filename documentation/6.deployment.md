# Deployment

> GitHub Actions builds the static site and deploys it to GitHub Pages with the official Pages actions. The published URL is set by the repository's Pages configuration, not by a committed file.

## Build Output

`npm run build` runs `vite build`. Vite writes to `docs/` because [`vite.config.ts`](../vite.config.ts) sets `build.outDir: "docs"`, wiping and recreating it each time; the same file also sets `base: "./"`, so emitted asset URLs are relative and the bundle serves correctly from either a domain root or a subpath. The result is a plain static bundle — `docs/index.html` with an empty `#app` plus hashed JS/CSS/assets — and because prerendering is disabled the app renders client-side after hydration (see [Architecture](2.architecture.md)). The build no longer generates a `CNAME`; under the Actions flow the custom domain lives in the repository's GitHub Pages settings, so no committed or generated `CNAME` file is involved.

## CI — `ci.yml`

[`ci.yml`](../.github/workflows/ci.yml) runs on pushes to `main` and on pull requests. All jobs run on `ubuntu-24.04` with Node `24.18.0`; all jobs run `npm ci` except `package-lock`, which runs `npm install --package-lock-only --no-audit --no-fund`:

| Job            | Steps                                                                                                       |
| -------------- | ----------------------------------------------------------------------------------------------------------- |
| `lint`         | `npm run lint`                                                                                               |
| `package-lock` | `npm install --package-lock-only --no-audit --no-fund`, then `git diff --exit-code` to reject lockfile drift |
| `typecheck`    | `npm run typecheck`                                                                                          |
| `build`        | `npx playwright install --with-deps chromium`, `npm run build`, `npm test`                                   |

The `package-lock` job is why to install with `npm ci` locally. The `build` job exercises the production build before the full Playwright suite.

## Deploy — `deploy-pages.yml`

[`deploy-pages.yml`](../.github/workflows/deploy-pages.yml) runs on pushes to `main` and manual dispatch, and uses the official GitHub Actions Pages deployment. Both jobs run on `ubuntu-24.04`; workflow permissions are `contents: read`, `pages: write` and `id-token: write`, and concurrency is grouped under `pages` with `cancel-in-progress: false`, so queued deployments do not cancel a run in progress.

The `build` job checks out the repo (`actions/checkout@v6`), sets up Node `24.18.0` with npm caching (`actions/setup-node@v6`), runs `npm ci` and `npm run build`, configures Pages (`actions/configure-pages@v6`), then uploads `docs/` as the Pages artifact (`actions/upload-pages-artifact@v5`, `path: docs`).

The `deploy` job depends on `build` and runs in the `github-pages` environment; it deploys the uploaded artifact with `actions/deploy-pages@v5`, exposing the published URL through that step's `page_url` output. This workflow only builds and deploys; testing is CI's job.

GitHub Pages for this repository is set to the **GitHub Actions** source (build type `workflow`): this fork publishes at [https://www.ogis.org/terra-draw-website/](https://www.ogis.org/terra-draw-website/), while upstream (terradraw.io) runs the same workflow file against its own Pages settings.

> [!NOTE]
> Both workflows trigger on `main` and pin Node `24.18.0`, so builds are verified on the same Node patch that publishes.

## Runtime CDN Dependencies

The deployed site is not self-contained. At runtime it loads Google Fonts, Leaflet CSS ([`index.html:13`](../index.html), unused), the Mapbox RTL text plugin, the Protomaps style and tiles (`white.json`/`black.json` by OS preference), and the external TypeDoc site in the API tab iframe. A CDN or network outage degrades the map, text rendering and the API tab; there is no offline mode.
