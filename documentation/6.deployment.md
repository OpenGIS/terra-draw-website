# Deployment

> GitHub Actions builds the static site and publishes it to the `gh-pages` branch, served at [terradraw.io](https://terradraw.io).

## Build Output

`npm run build` runs `vite build && echo 'terradraw.io' > docs/CNAME` (`package.json:8`). Vite writes to `docs/` because [`vite.config.ts:6-8`](../vite.config.ts) sets `build.outDir: "docs"`, wiping and recreating it each time.

The result is a plain static bundle: `docs/index.html`, hashed JS/CSS/assets and a generated `CNAME` file. Because prerendering is disabled, `index.html` contains an empty `#app` and the app renders client-side after hydration — see [Architecture](2.architecture.md).

> [!WARNING]
> `docs/` is **build output**, not documentation. It is gitignored ([`.gitignore:5`](../.gitignore)) and overwritten by every build. Developer docs live in `documentation/`.

A `CNAME` file is also committed at the repo root, but that copy is not what GitHub Pages serves — the published one is `docs/CNAME` on the `gh-pages` branch, generated during deploy.

## CI — `ci.yml`

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) runs on pushes to `main` and on pull requests (opened, synchronised, reopened, ready for review). All jobs run on `ubuntu-24.04` with Node `24.18.0` and `npm ci`:

| Job             | Steps                                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------------------------ |
| `lint`          | `npm run lint`                                                                                                |
| `package-lock`  | `npm install --package-lock-only --no-audit --no-fund`, then `git diff --exit-code` to reject uncommitted lockfile changes |
| `typecheck`     | `npm run typecheck`                                                                                           |
| `build`         | `npx playwright install --with-deps chromium`, `npm run build`, `npm test`                                    |

The `package-lock` job is the reason to install with `npm ci` locally rather than letting `npm install` rewrite the lockfile. The `build` job exercises the real production build before running the full Playwright suite — smoke, drawing, export, theming, fixture and capture-guard meta-tests, the committed documentation captures and the twelve-capture responsivity matrix (see [Testing](5.testing.md)).

## Deploy — `deploy-pages.yml`

[`.github/workflows/deploy-pages.yml`](../.github/workflows/deploy-pages.yml) runs on pushes to `main` and on manual dispatch. It has `contents: write` and a `deploy-pages` concurrency group with `cancel-in-progress: true`, so only one deployment runs at a time.

The deploy job (`deploy-pages.yml:20-64`):

1. Checks out `main` with full history and sets up Node `24.14.1` with npm caching.
2. Runs `npm ci` and `npm run build`.
3. Fetches the `gh-pages` branch, removes `/tmp/gh-pages`, and attaches it as a worktree.
4. Replaces `/tmp/gh-pages/docs` with the fresh build via `rsync -a docs/ /tmp/gh-pages/docs/`.
5. Commits `Deploy docs from <sha>` and pushes to `gh-pages` — unless the diff is empty, in which case it exits early.

GitHub Pages is configured to serve the **`gh-pages` branch, `/docs` folder**, with `terradraw.io` as the custom domain. The workflow comment notes the `gh-pages` branch is expected to already exist, so first-time setup for a fork requires creating it before the publish step can succeed. This workflow builds only; testing is the CI pipeline's responsibility.

> [!NOTE]
> Both workflows trigger on `main`, which is this repository's authoritative branch. Work on a branch or PR; merges to `main` are what build, test and deploy.

## Node Version Pins

| Context             | Node version | Source                                              |
| ------------------- | ------------ | --------------------------------------------------- |
| Local development   | 24 (npm 11)  | [`README.md`](../README.md)                          |
| CI                  | `24.18.0`    | [`ci.yml:20`](../.github/workflows/ci.yml)           |
| Deploy              | `24.14.1`    | [`deploy-pages.yml:29`](../.github/workflows/deploy-pages.yml) |

The CI and deploy pins are not identical; both are Node 24, but builds are verified on a slightly newer patch than the one used to publish. Aligning them would remove a small class of "passes CI, fails deploy" surprises.

## Runtime CDN Dependencies

The deployed site is not self-contained. At runtime it loads:

- Google Fonts (Open Sans) — `index.html:10-12`
- Leaflet CSS from unpkg — `index.html:13-14` (unused at runtime; see [Architecture](2.architecture.md))
- The Mapbox RTL text plugin from unpkg — [`setup-maplibre.ts:58-63`](../src/routes/home/setup-maplibre.ts)
- Map tiles and the Protomaps style — light `white.json` or dark `black.json`, chosen from the OS preference — [`setup-maplibre.ts:66-68`](../src/routes/home/setup-maplibre.ts)
- The external TypeDoc site in the API tab iframe — [`api-docs/index.tsx:9`](../src/routes/api-docs/index.tsx), which itself renders dark when the page does

A CDN or network outage degrades the map (no style/tiles), text rendering and the API tab. There is no offline mode despite the leftover service worker and manifest stubs.
